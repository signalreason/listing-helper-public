# Security reports

Do not report credentials, private listing data, or exploitable security details in a
public issue or pull request.

Open this repository's **Security** tab and select **Report a vulnerability** to send a
private report to its maintainers. If that option is unavailable, do not post the
technical details publicly. Ask the maintainers to enable private reporting using an
issue that says only that you need a private security contact.

Include the affected revision, a description, and steps using invented data. Remove
credentials, personal information, and real seller data from attachments. Do not test
another person's installation without permission.

Only the current main branch is maintained. Security responses are best effort, with no
guaranteed response time. Operators must review and deploy fixes to their own copies.

If you exposed a credential, revoke or rotate it with its provider first. Removing a
file from the latest commit does not remove it from history. See
[GitHub's removal procedure](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).
